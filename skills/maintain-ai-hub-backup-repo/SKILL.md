# Maintain the AI hub repo

Companion to `~/.copilot/instructions/coding-agents.instructions.md` (global rules and skill map) and to `maintain-global-agent-config` (what may change and the disclosure duty); this file covers the backup repo and sync only.

`~/dev/ai` (GitHub: will12193/ai) is a **backup** of shareable Copilot config. `~/.copilot` is the source of truth; the repo is overwritten from it by the sync script. Two equivalent scripts exist: `sync.sh` (bash, rsync, python3) and `sync.ps1` (Windows PowerShell 5.1, no extra tools). Use whichever matches the machine; below, "the sync script" means either. On the Windows home machine the repo is at `C:\Users\willc\Documents\dev\ai` (see `windows-home-machine`).

## Golden rule

**Never edit `skills/`, `instructions/` or `mcp-config.redacted.json` in the repo.** Those edits are destroyed on the next sync. Change the real files in `~/.copilot` first, then sync. (`sync.sh` refuses to run if those paths have uncommitted changes, so a mistake here shows up as an abort, not silent loss.)

Any change to files under `~/.copilot` must also follow `maintain-global-agent-config` (disclose it under a "Global Agent Behaviour Change" header at the end of the message).

| Repo path | Source of truth |
|---|---|
| `skills/` | `~/.copilot/skills/` |
| `instructions/` | `~/.copilot/instructions/` |
| `mcp-config.redacted.json` | generated from `~/.copilot/mcp-config.json` (secrets redacted) |
| `README.md` tables between the `GENERATED` markers | generated by the sync script from each file's frontmatter |
| Rest of `README.md`, `sync.sh`, `sync.ps1`, `.gitignore`, `.gitattributes` | edited directly in the repo (not synced) |

## Workflow for any requested change

1. Make the change in `~/.copilot` (skill, instruction, MCP config). Write frontmatter `description`s so the part before `Use when:` reads as a one-line human summary; the README is generated from it.
2. If the hand-written parts of `README.md`, the sync scripts or `.gitignore` need changing, edit them in the repo now, before syncing.
3. Run the sync script with `"<what changed and why>"`: `~/dev/ai/sync.sh "<msg>"`, or on Windows `powershell -NoProfile -ExecutionPolicy Bypass -File C:\Users\willc\Documents\dev\ai\sync.ps1 "<msg>"`. The message is the commit message; make it say the intent (e.g. `"Add health-check skill for context read-outs"`), not just "update". Without an argument it falls back to `Backup <date>`. The script pulls (fast-forward only), copies, regenerates the README tables, scans for secrets, commits and pushes. Do not run a separate commit/push for synced content.
4. Verify: the output says `Backed up.` (or `No changes to back up.`), and `git -C <repo> status -s` is clean.
5. Run edits and the sync as **separate steps**, never in the same tool batch, or an edit can land after the script's `git add`.

## Sync failures

- `Repo has uncommitted changes in synced paths` → someone edited synced files in the repo. Compare with `~/.copilot`, port anything wanted into `~/.copilot`, then `git -C <repo> checkout -- <paths>` and re-run.
- `Possible secret found` → stop, tell the user which file, do not push.
- `sync.ps1` push fails with `Permission denied (publickey)` → ssh-agent has no key; see `windows-home-machine`.

## Platform differences

- `sync.ps1` normalises CRLF to LF on copy (Windows `~/.copilot` files are CRLF; the repo stores LF, enforced by `.gitattributes`). Without that every file would show as changed.
- `sync.ps1` does not redact `mcp-config.json`: it leaves `mcp-config.redacted.json` untouched and prints a note if the source exists. Port the redaction before relying on it.
- Each machine's sync mirrors its own `~/.copilot` with delete semantics. A skill that exists only on another machine's `~/.copilot` is removed from the repo by the next sync here (and the reverse). Keep the machines' skill sets in step by restoring from the repo before adding things on a second machine.

## README requirements

`README.md` is for humans. The Instructions and Skills tables are generated; keep the hand-written parts accurate: what the repo is, how sync/restore works, the MCP note, and what is deliberately not backed up.

## Don'ts

- Don't back up session history, databases, logs, or the unredacted `mcp-config.json`.
- Don't commit secrets; keep the sync's secret scan in place.
- Don't hand-edit synced files or the generated README tables.
